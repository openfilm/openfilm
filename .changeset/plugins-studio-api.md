A plugin's element now reaches Studio through one public module, `openfilm/studio`, named by the page's import map: the project shown as a value it is told about as it changes (its name, folder, files and how they were made), its `film.html` read and written by clip id as the edit writes it, the toast, Settings, the app's chat (`refer`, `select`, `hover`, in the desktop app), the app's commands, files put into another plugin's workbench (`addTo('edit', [path])`) and what its own takes (`provide`), buttons of its own on the top bar (`topBar.set`), and its plugin's own server routes and events (`pluginApi`). `openfilm/studio/react` is the same for React, and the import map also names `react`, `react-dom`, `react-dom/client` and `react/jsx-runtime`, Studio's own copy. The Canvas uses only this module, as anyone's plugin does. How to make a plugin, and the whole interface, is in `plugins/README.md`. A plugin's element is now also told its workbench's name, as `plugin`.
