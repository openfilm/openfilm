# OpenFilm 资源中心：调研与交互设计建议

研究日期：2026-11-15。范围：新版仓库实现、Apple Final Cut Pro、Adobe Premiere/Bridge/Stock、DaVinci Resolve、Kyno、NeoFinder、Frame.io、BaseHead 的官方资料，以及公开的一手用户反馈。这里的优先级是产品设计判断；社区帖子能证明问题真实存在、长期反复发生，不能用于估计 OpenFilm 用户的发生率。本轮交付为研究和方案，应用功能仍以当前实现为准。

## 1. 建议先确定的产品结构

全局窗口命名为 **资源中心**，承载 **项目 / 素材库 / 在线资源** 三个工作域。编辑器内承载本项目文件的区域明确命名为 **项目素材**。跨项目个人集合称 **素材库**，替换当前语义不完整的“我的”。

- 资源中心回答：我拥有或连接了什么？在哪里？如何整理、寻找、复用？
- 项目素材回答：这个项目引用了什么？哪些已上时间线？使用了哪段？能否完整交付？
- 在线资源回答：我还能从哪些已支持的来源发现、预览和获取资源？

共用素材身份、元数据、预览、导入和引用关系，按使用场景提供不同视图。项目管理与素材管理各自有导航、筛选和操作；不将项目缩略图和素材文件放进同一条“全部”列表。

**三个组织维度必须独立：** 存储位置表示实际目录或来源；素材集表示人为选择的一组素材；智能素材集表示一组持续执行的筛选条件。视频/图片/音频是筛选维度，不应与硬盘、品牌集合、项目并列成同一种目录。

## 2. 长期痛点及其界面含义

| 痛点 | 一手证据 | 对 OpenFilm 的要求 |
| --- | --- | --- |
| 文件移动、换盘后断链，修复过程反复、易误配 | Adobe 社区 2017 年移动素材后重连问题，后续仍有讨论；另有用户报告相同文件名误链接。 | 明确区分盘未连接、路径失效、无权限、云端未下载；批量重新定位根目录；展示匹配依据和受影响项目。 |
| 大体量素材不愿再复制一份 | Eagle 用户描述数 TB 存量素材无法承受重复复制。 | “连接现有文件夹”与“复制到素材库”分开；添加外部位置默认建索引，不搬原文件。 |
| 跨项目复用造成重复条目，清理工具不能解释差别 | Premiere 去重反馈帖始于 2021 年，截至 2026 年仍有追加反馈。 | 区分同文件、多位置副本、版本、相似内容和项目实例；候选重复可比较，不能只按名称或大小合并。 |
| 记得画面或一句话，不记得文件名 | Premiere 的语义画面搜索及其社区反馈直接围绕这个需求；用户还要求排除已选过的片段。 | 文件、元数据、逐字稿、画面和片段标记可共同检索；命中跳到时间范围；可筛掉本项目已用范围。 |
| 每个素材只能归一个目录，整理方式互相冲突 | Bridge Collections 与 Frame.io Collections 都通过集合/保存条件避免重新移动文件。 | 同一素材可以属于多个素材集；移出集合与移动文件是两种不同操作。 |
| 硬盘不在线就无法知道盘里是什么 | NeoFinder 专门保留磁盘目录、缩略图、元数据，支持盘不在线时查询。 | 外接盘离线仍保留目录、预览缓存和查找结果，明确完整播放是否可用。 |
| 标签、评级、整理成果被软件锁住 | Eagle 用户明确担心原有 Finder/Bridge 等整理无法迁入，也无法带标签迁出。 | 提供元数据导入导出、来源与格式说明、集合清单备份；按文件格式支持 XMP 或旁车；无法映射时保留原字段。 |
| 找到整个文件以后，还要再次找真正需要的几秒 | Kyno 的标记/子片段和 BaseHead 的波形选段都把选择范围直接带到下游编辑。 | 预览时标 I/O、标记、保存选段，拖进时间线携带范围；不要强制先导出截短的新文件。 |
| 不知道哪里用过，担心整理或删除会破坏旧项目 | BaseHead 的项目视图可以反查历史项目使用过的声音；Premiere 用户也请求从素材直达时间线。 | 详情有“使用位置”，能跳到项目、序列和时间码；删除前说明已知引用与未检查范围。 |

## 3. 成熟产品的取舍

| 产品 | 官方资料确认的机制 | 可以吸收的部分 | 需要结合 OpenFilm 调整的部分 |
| --- | --- | --- | --- |
| Final Cut Pro | 将托管媒体、外部媒体和后台生成媒体分开；提供收集媒体以迁移或归档。 | 外链和可携带副本共存；缓存与原素材分账；迁移前做依赖检查。 | 不要求普通用户先理解 Library/Event 等专业层级；操作名称直接说明文件后果。 |
| Resolve | Media Storage 与当前项目 Media Pool 分开；Smart Bins 自动按元数据分组；Power Bins 跨项目复用。 | 全局来源与项目工作集分开，支持跨项目通用资产。 | 中文直接用“素材库”“项目素材”“智能素材集”；不照搬多个 Bin 名词。 |
| Bridge | 集合、智能集合、文件夹、关键词各有职责。 | 逻辑整理不要求复制或移动原文件。 | 视频与声音应有时间范围、波形、项目使用关系，超过通用文件浏览能力。 |
| Kyno | 无需预先导入即可浏览；Drilldown 跨层平铺；标记和子片段可向 NLE 传递；作者元数据用旁车保存。 | 快速筛片、不破坏磁盘目录、保存选段与导出整理成果。 | FAQ 明确其无“所有看过内容”的全局搜索；OpenFilm 应另设持久目录索引。 |
| NeoFinder | 磁盘目录、技术元数据和缩略图入目录，离线可查询。 | 多盘、NAS 与归档盘的长期管理。 | 离线能搜索不等于离线有原文件可播放或导出，界面要分清。 |
| Frame.io | 元数据驱动 Collections，支持私有与团队集合；版本堆栈有独立模型。 | 按任务保存视图、版本归组、收藏与物理目录分离。 | 当前产品先做好本地/外部来源；团队权限和同步需独立设计后上线。 |
| BaseHead | 可选波形范围并拖入下游；能查当前和历史项目的素材使用。 | 找到、试听、选段、放入项目形成短路径。 | 不用复杂音频工程术语；适配图片、视频、页面、片段组。 |

## 4. 新版代码的真实起点

以下是代码审阅结果，不代表所有路径都已在实际设备上验收：

| 能力 | 当前基础 | 设计需要补上的内容 |
| --- | --- | --- |
| 项目管理 | `ProjectsView.tsx` 已有文件夹、路径、前后导航、搜索、多选；新版本将示例移入侧栏并提供存储入口。 | 放进资源中心的“项目”工作域，保持现有习惯。 |
| 项目素材 | `MediaPool.tsx` 已有文件夹、筛选、搜索、缩略图、选择、拖入时间线、外链状态、收集/重新链接。 | 作为“项目素材”的工作视图，增加完整使用关系和明确的项目范围。 |
| 跨项目个人素材 | `saved.mjs`、`lib/saved.ts` 支持文件、页面、片段和片段组；带依赖保存；`shell/library.tsx` 在 project/saved 间切换。 | 将“我的”重命名为“素材库”，共享给全局管理界面，而不是另建孤立数据。 |
| 外部来源 | `files.mjs` 支持 copy/link/auto；Saved 可包含用户连接的目录。 | 为连接来源提供一级位置入口、稳定状态和显式的文件处理策略。 |
| 断链与查重基础 | `media-index.mjs` 保存项目记录，`media-reconnect.mjs` 分层定位；现有指纹读取大小与头/中/尾片段。 | 不能把抽样指纹称为完整内容哈希；自动删除或合并前要做更强校验；还需持久来源索引和版本身份。 |
| AI 来源与版本 | `media-made.mjs` 已记录提示词、模型、引用文件、版本关系；当前素材面板已有堆栈展示接口。 | 提升为全局资产元数据和可筛选的详情，保留项目版本快照。 |
| 内置与社区资源 | `lib/library.ts`、`server/library.mjs` 以及 Drawer 类别已存在。 | 发现页与个人拥有的素材分开；下载使用后仍显示统一的项目素材关系。 |

特别要避免两个误判：

1. `media-library.mjs` 当前的个人素材检索以 Saved 为边界，遍历最多 5,000 文件、6 层，返回结果最多 2,000；这是现有检索接口的边界，不是一个已支持任意规模的全局目录数据库。UI 的 Saved 列表另有遍历路径，不能用这个限制推断整个产品的统一容量。
2. `bringIn(..., 'auto')` 会依次尝试克隆、硬链接，大文件可能转外链，其余复制。界面应在导入结果中说明实际模式。硬链接不能被当作天然的版本隔离承诺；会改写内容的操作需生成独立版本或先断开共享。

## 5. 命名与侧栏

### 名称

| 位置 | 建议文案 | 英文建议 |
| --- | --- | --- |
| 全局入口/窗口 | 资源中心 | Library |
| 全局个人资产域 | 素材库 | My Assets |
| 当前项目文件工作区 | 项目素材 | Project Assets |
| 项目内浏览全局素材 | 素材库 | My Assets |
| 当前“保存到我的” | 保存到素材库 | Save to My Assets |
| 包含多个素材的逻辑集合 | 素材集 | Collection |
| 保存规则的集合 | 智能素材集 | Smart Collection |
| 真实磁盘或目录 | 存储位置 / 文件夹 | Locations / Folders |
| 外链实际文件 | 在原位置使用 | Reference in place |
| 为项目准备独立文件 | 复制到项目 | Copy into project |

编辑器承载模板、声音、字幕、特效等的整个区域可以称“素材与效果”或沿用工具栏各类名称；“项目素材”只指其中当前项目文件的范围，避免把所有效果商店内容叫作项目素材。

### 全局入口固定三个工作域，域内再显示相关侧栏

```text
资源中心
  项目                 # 现有项目管理
  素材库               # 跨项目个人资产与已连接目录
  在线资源             # OpenFilm 内置、社区、实际已支持的在线来源
```

项目域：我的项目、最近打开、示例项目、用户项目文件夹。项目条目提供“查看素材”，无需打开旧项目的剪辑台即可浏览、选段和复用；当前项目与旧项目分别标识。项目文件夹的管理语义维持现状；示例项目不混入个人素材搜索结果。

素材域侧栏：

```text
快速访问
  全部素材
  最近添加
  星标
  待整理                 # 收集入口启用或有内容时显示

我的整理
  素材集                 # 用户自己的集合，可固定常用项
    品牌 A
    城市 B-roll
  智能素材集             # 保存筛选规则，有规则后展开
    竖屏且时长小于 15 秒

存储位置
  OpenFilm 素材          # 应用托管的个人素材
  拍摄 SSD               # 用户授权连接的目录，展开是真实目录树
  工作室 NAS             # 在线/离线状态，不因离线消失
  添加位置…

底部固定
  后台任务               # 索引、预览、转写、代理、下载、复制
  存储与维护             # 原文件/项目副本/缓存/代理占用分开
```

“待整理”是显式工作流状态；将素材标为已整理后离开该视图，不强迫每个素材必须加标签。星标是轻量评价；素材集是任务/用途组织；两者不重复定义。

“全部素材”的默认范围是托管个人素材和用户主动连接的位置。项目专有素材可从“查看素材”进入，或由用户选择项目来源加入全局索引；AI 中间结果和缓存不自动扩散到个人素材库。

“智能素材集”放规则，不自动为每个标签生成一行。“视频/图片/音频/模板”“横竖屏”“授权状态”“已用/未用”放上方筛选，用户可把常用组合保存或固定。

“离线/失效”“候选重复”“回收站”收在存储与维护页，以问题数量提示；不要默认铺满导航。回收站明确指应用移除的条目还是实际磁盘文件，不冒充系统全盘废纸篓。

在线域：OpenFilm 内置、社区资源、已连接来源、获取记录。只展示真实可接入的服务。在线查询与本地查询有显式范围；下载或保存后建立来源记录，并在素材库出现同一个资产身份。用户现有 Eagle/Bridge 等外部目录可先以文件夹接入；专用连接器另做能力映射，不承诺直接改写第三方目录数据库。

侧栏支持折叠、常用固定、来源排序。无内容的进阶组按需显示；初次使用先提供导入文件、连接文件夹、从项目保存三个明确入口。

## 6. 主体与详情区

中心：路径/查询范围 → 搜索与筛选 → 网格/详细列表 → 状态栏。右侧详情可收起，单击选中时保持上下文，双击进入大预览；素材的双击不直接放进时间线。项目条目的双击仍打开项目。

- 网格保留封面、可读名称、时长、来源/离线/使用状态，缩略图大小可调。
- 列表默认名称、类型、时长、分辨率、来源、项目使用；列可选择。批量改标签和集合时保留多选。
- 影片有胶片条、声音有波形，空格预览；I/O 保存范围，J/K/L 等快捷键与编辑器保持一致，并遵循焦点作用域。
- 多选详情展示共同值及“多个值”，支持增添/移除标签和加入集合，避免用一个空值覆盖差异。
- 详情以“预览、标记/选段、来源和位置、使用位置、版本”渐进展开；版权与技术参数按需查看。
- 路径可以“在访达/资源管理器中显示”，资产显示名称与磁盘文件名分开；重命名显示名称不直接改原文件。

检索范围始终可见：全部已连接位置、当前位置及子文件夹、本项目、在线来源。文件夹默认按当前目录浏览；搜索时清楚显示是否包含子文件夹。语义搜索结果说明命中类型和时间范围，例如“逐字稿 00:18–00:22”“画面匹配 00:08–00:12”“人工标记”。

“未建立索引”与“没有匹配结果”分开。后台索引可暂停、取消和继续；技术信息先入索引，缩略图/波形其次，转写和语义分析按范围选择。操作先可用，再逐渐丰富内容。代理、波形、封面和语义索引是同一素材的派生物，不能撑大“素材数量”。

Adobe 的现行搜索把画面描述、逐字稿和元数据结合，文档同时说明分析状态和本机处理；这说明方向可行，但不构成 OpenFilm 已拥有相同模型、准确率或语言覆盖的证据。[官方搜索说明](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/search-for-media-using-ai-powered-media-intelligence.html)、[分析与索引 FAQ](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/media-intelligence-and-search-panel.html)。

## 7. 与项目内素材配合的明确规则

项目内“素材”工具中使用两个清楚的范围：**项目素材 / 素材库**。另有打开完整资源中心的按钮；模板/文本/特效等现有工具入口保留。

项目素材顶部以筛选表示“全部、已用、未用、离线”；其中“已用/未用”针对当前项目、明确序列范围。一个长视频可有已用与未用范围，不因使用过几秒就把整条素材排除。

**浏览、加入、上时间线是三步，后两步可以合并执行：**

1. 浏览素材库、查看详情或试听，不会把文件加进项目。
2. “加入项目”建立项目绑定，让素材出现在项目素材中，不会新增时间线片段。
3. 拖到时间线或“插入到播放头”，同时加入项目并插入当前选段。已加入的素材复用已有项目绑定，不重复导入。

资源中心的主操作显示明确目标项目；无项目打开时，提供选择项目或新建项目。项目内则使用当前项目，不反复要求选择。

使用策略在加入项目时说明，按项目或位置记住偏好：

- 在原位置使用：原文件仍在外接盘/NAS；详情清楚显示依赖该来源。
- 复制到项目：项目拥有可携带的文件副本，复制状态与实际占用可查询。
- 为外链项目提供“收集媒体到项目”：交付前补齐所需依赖并验证，不将代理误作原片。

图片/音频/视频在项目中的裁切、变速、调色不改变素材库的原素材。素材库出现新版本时，项目默认继续使用原版本；提供“发现新版本 → 比较 → 更新此项目”的操作，不静默替换所有项目。

项目中精修的片头或片段组可以“保存到素材库”，连同依赖保存成可复用资产。项目素材的文件夹保持其项目内组织；素材库的集合不被导入成物理文件夹。标签与标记可带入，项目自己的名称、整理和选段保存在项目范围。

素材也应能直接发给助手。当前 `referOutside` 会先把 Saved 文件带入项目，第一期可以把这个动作明确标作“加入项目并发给助手”；未来采用稳定资产引用后，再支持纯参考而不加入。助手搜索与人工界面共用资产身份、来源状态和加入项目规则；“找一段夜景”仍应返回可查看的候选与时间范围。

“使用位置”能双向跳转：全局素材 → 项目 → 时间线范围；项目素材 → 素材库原条目 → 实际来源目录。已索引的历史项目可以参与反查；扫描不完整时写“已知用于 3 个项目，2 个项目尚未检查”，不能据此宣布可安全删除。

## 8. 外部来源、在线素材和 AI 素材

### 连接目录

“添加位置”选择本机目录、外接盘或已挂载的 NAS。默认只建立目录索引，保留原层级，不搬走原文件；可选是否含子文件夹、是否创建离线预览。后台增量更新，重新接盘后自动校验。临时浏览与长期连接作为不同动作，防止每次浏览都把目录加入长期索引。

目录名、显示名、磁盘标识和实际路径分开；盘符/卷名只用于定位提示。索引关联稳定的来源身份和相对路径，并用文件信息验证。用户未连接的目录不自动扫描。浏览器版与桌面版依据实际文件访问能力给出不同入口，不把浏览器上传说成原位置引用。

### 在线来源

保存源网址、作者/提供方、外部资产编号、获取时间、原始文件与预览的关系、下载位置、授权记录或待确认状态。预览、已下载、授权记录是不同状态，互不推断。用户添加网页链接时，可先作为参考项进入待整理，获取成功后转为可用文件；原来源保留。

Adobe Stock 官方界面就把预览、获取和授权历史分开，这可用于设计记录机制；具体接入要逐个服务确认能力。[Adobe Stock 官方说明](https://helpx.adobe.com/stock/web/help/using-adobe-stock-website.html)。

### AI 生成及变体

生成结果仍是普通视频/图片/音频资产；来源属性记录生成服务、模型、提示词、参考文件、生成时间及可用参数。以版本/派生关系归组，手工选择才提升为跨项目资产；不强制把所有项目中间结果暴露到个人素材库。

语义推断标签与人工标签分开，支持批量接受、修改、撤销；搜索结果可用但不能伪装成已确认的人工描述。云端分析需要明确传出内容和触发方式；本机索引不自动触发下载云盘占位文件。

## 9. 文件操作与生命周期

| 所在视图 | 普通整理操作 | 明确有文件后果的操作 |
| --- | --- | --- |
| 素材集 | 加入/移出素材集，只改变关系 | 另列“定位原文件”“移动原文件…” |
| 外部位置 | 更改显示名、标签、评价；停止连接不删磁盘文件 | 移动/重命名/移到系统回收站单独说明路径与已知引用 |
| 项目素材 | 从项目移除与删除时间线实例分开 | 删除项目副本时检查其在项目内的依赖；外链原文件不随项目删除 |
| 素材库托管文件 | 取消收藏、移除目录记录 | 删除托管文件需报告依赖项目与副本范围 |
| 维护页面 | 清理重建型缓存、查看离线原因 | 去重/换源先预览差异与引用更新计划；保留恢复手段 |

拖到素材集表示加入集合；拖到项目表示加入项目；拖到时间线表示插入选段；拖到真实文件夹时必须明确其为实际移动。用落点提示和菜单区分，避免一个“移动”覆盖几种不同语义。

单击选择、双击打开/预览、Shift 连选、⌘/Ctrl 多选、空白框选、方向键浏览、空格预览、搜索与右键形成统一交互；平台原生快捷键与编辑器焦点规则需专门做回归。

## 10. 支撑界面的数据关系

这是建议模型，非当前已实现的接口：

```text
Asset（稳定资产身份）
 ├─ AssetVersion（不可变内容版本）
 │   ├─ FileLocation[]（一个内容可在多个位置存在）
 │   ├─ DerivedRepresentation[]（代理/缩略图/波形/分析缓存）
 │   └─ Segment[]（标记、转写时间范围、收藏选段）
 ├─ CollectionMembership[] / SmartCollectionRule
 ├─ Provenance / RightsRecord / UserMetadata
 └─ ProjectBinding[] → TimelineUsage[]
```

路径不是资产 ID；相同内容在多个位置不等于多个素材；同一个素材的新内容不应悄悄覆盖旧版本。快速指纹用于候选定位，破坏性去重需完整校验。代理依赖特定版本；重连不能把不同版本误接到原项目。

目录索引和可重建缓存分开；人工标签、标记、集合、来源和引用属于需要持久备份的数据。元数据导出要明确能往返的字段；视频选段/AI 来源等专有字段可用有版本的开放 JSON/CSV/旁车清单携带，不能承诺所有第三方都能直接理解。

界面组件共用 `AssetBrowser`、`AssetPreview`、`AssetInspector`、`LocationPicker`、`ImportPlan` 与选择/快捷键规则；上下文通过 Global / Project / Collection / Location 区分。不要为了两个入口复制两套文件列表和数据接口。

## 11. 建议实施次序与验收

### 首个闭环

命名统一、全局素材域、复用 Saved、持久来源索引、位置导航、显式连接目录、清楚的加入项目/插入片段、来源和离线状态、逻辑素材集、项目使用关系。外部来源、跨项目使用与文件后果属于第一期基础，不能只完成一个更大的图库。

### 大量素材工作流

持久增量索引、虚拟化网格/列表、技术信息快速筛选、批量元数据、智能素材集、离线目录、选段和转写检索、后台任务及依赖检查。先测真实大目录，再确定技术阈值和性能指标；候选去重先提供比较而非自动删除。

### 进一步扩展

画面语义搜索、相似镜头/音效、跨项目版本比较、外部应用专用连接、团队共享与权限。团队协作不是往个人素材库上加一个“共享”按钮，需要独立处理来源权限、修改冲突、版本更新和授权记录范围。

关键验收场景：

1. 连接用户提供的多层拍摄目录，原文件数量和路径不变；索引中断后能续扫。
2. 拔掉拍摄盘，仍能查到目录和元数据；界面准确说明预览/代理/原文件各自是否可用。
3. 同一片段从多个集合加入同一项目，不创建多余绑定；同名异内容不会误合并。
4. 拖入选中的 4 秒范围，时间线范围正确；只浏览时项目文件与素材数量不变。
5. 全局调整集合不影响时间线；库版本更新不静默改旧项目。
6. 复制到项目并收集依赖后，断开外部盘仍能按所选交付规格打开和导出；缺失原片明确报告。
7. 删除/清理能解释对象、路径、已知引用、未检查项目和恢复方式。
8. 素材标签与集合导出后可重建；缓存清理不丢人工整理。
9. 两处显示相同名称、星标、来源、离线状态；项目标记/选段按作用域清楚区分。
10. 使用经过声明的设备和目录规模测量首屏、翻页、搜索、后台任务对播放的影响；验收数据需实测，不以演示数据冒充。

## 12. 建议下一步验证的用户任务

用个人创作者、自由剪辑师、小型工作室各自的真实目录做任务测试：连接一块旧盘；从旧项目找一段音效；从长视频找一句话；将素材加入两个用途不同的集合；选一段放入当前项目；离线打开旧项目；收集并交付；在不损坏项目的前提下清理重复候选。

观察完成路径、误解、恢复能力及是否需要回到访达/资源管理器，之后再量化优先级。原有“项目文件夹”“素材文件夹”“素材集”的区别，以及“加入项目”和“插入时间线”的区别，是最应该先验证的两个认知点。
